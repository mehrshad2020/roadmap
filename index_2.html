مهارت‌هایی که جونیورها در عصر AI باید بلد باشن

بازار کار جونیور سخت‌تر شده، ولی نه چون AI جای برنامه‌نویس رو گرفته — چون کاری که قبلاً کارِ جونیور بود (بویلرپلیت، CRUD ساده، تست‌های ابتدایی، مستندات) حالا رو دوش AI افتاده. شرکت‌ها دیگه برای «کدنویسی» جونیور استخدام نمی‌کنن.

جمله‌ی محوری: AI کدنویسی رو ارزون کرد، پس قضاوت مهندسی گرون شد. جونیوری استخدام می‌شه که بتونه کدِ AI رو رد کنه و دلیلش رو توضیح بده.
۴۴٪از تسک‌های تولید کد با AI، آسیب‌پذیری امنیتی وارد کد می‌کنن
۸۴٪توسعه‌دهنده‌ها از AI استفاده می‌کنن یا قصد دارن بکنن
۲۹٪فقط همین‌قدر به خروجی AI اعتماد دارن — و رو به کاهش
۷۱٪مدیران مهندسی: ارزیابی توانایی واقعی کاندیدا سخت‌تر شده

⚡ اگه فقط ۵ دقیقه وقت داری

  1. کد AI رو بازبینی کن، نه اینکه فقط قبولش کنی. این تنها مهارتیه که همه‌ی مصاحبه‌کننده‌ها دنبالشن.
  2. فاندامنتال‌ها ارزشمندتر شدن، نه کم‌ارزش‌تر. دیتابیس، دیباگ، HTTP، تست.
  3. یک پروژه‌ی دیپلوی‌شده‌ی زنده از ده ریپوی نیمه‌کاره ارزشمندتره.
  4. بتون توضیح بدی چرا این تصمیم رو گرفتی. مصاحبه‌ی ۲۰۲۶ روی استدلال می‌چرخه، نه سینتکس.
  5. یک لایه‌ی AI واقعی بساز (RAG، ایجنت، MCP) — نه فقط «بلدم با ChatGPT کار کنم».

بخش اول — مهارت‌های فنی

۱ مهارت‌های AI (پایه)

این‌ها دیگه «مزیت رقابتی» نیستن، شرط لازم‌ان. نبودشون یعنی رد شدن در مرحله‌ی اول.

کار حرفه‌ای با کدینگ ایجنت‌ها پرتکرارترین سؤال مصاحبه Copilot / Claude Code / Cursor — کانتکست درست دادن، شکستن تسک به قدم‌های کوچیک، و جلوگیری از تغییرات بزرگ یک‌جا. تفاوت جونیور خوب و بد اینجا معلوم می‌شه: یکی تسک رو تکه‌تکه می‌ده، اون یکی می‌گه «کل پروژه رو بنویس».
بازبینی و رد کردن کدِ AI مهم‌ترین مهارت این لیست بتونی بگی این کد کجاش edge case نداره، کجاش N+1 query داره، کجاش ورودی ولیدیت نشده، کجاش خطا رو بی‌صدا می‌خوره. کسی که کد AI رو بدون فهمیدن مرج می‌کنه، سر اولین سؤالِ «چرا؟» لو می‌ره.
ساختن با AI، نه فقط استفاده از AI یک API که به LLM وصل می‌شه، RAG ساده، embedding و vector search، function calling. لازم نیست مدل ترین کنی — لازمه بلد باشی AI رو به یک محصول واقعی بچسبونی.
درک محدودیت‌ها و ریسک‌ها هالوسینیشن، هزینه‌ی توکن، لتنسی، rate limit، و امنیت prompt injection. بدونی کجا اصلاً نباید از AI استفاده کنی.

۲ مهارت‌های AI-native تمایزساز

این‌ها هنوز کمیاب‌ان. اگه یکی‌شون رو بلد باشی، از اکثر جونیورهای بازار جلو می‌افتی.

چرا مهم‌ان؟ چون شرکت‌ها از «استفاده از AI» رد شدن و رسیدن به «ساختن سیستم‌هایی که AI درش کار می‌کنه». کسی که این لایه رو بلده، عملاً کارِ میدلِوِل انجام می‌ده.
Context Engineering مرتب نگه داشتن کدبیس و نوشتن دستورالعمل/قواعد پروژه طوری که ایجنت درست کار کنه — نه کم‌اطلاعات، نه غرق در جزئیات. این دیگه یک مهارت مستقله، نه «پرامپت‌نویسی».
Spec-Driven Development اول اسپک دقیق می‌نویسی، بعد ایجنت کد می‌زنه، بعد خروجی رو با اسپک تطبیق می‌دی. روش غالب کار تیمی با ایجنت‌ها در ۲۰۲۶.
ساختن MCP Server پروتکلی که ایجنت‌ها از طریقش به داده و ابزار بیرونی وصل می‌شن. الان تقریباً در حد «بلد بودن ساخت REST API» داره ضروری می‌شه.
ساختن یک ایجنت ساده حتی یک ایجنت کوچک با حلقه‌ی tool-calling. تا از داخل نسازیش، نمی‌فهمی چرا گاهی جواب نمی‌ده.
Evals و Observability برای فیچرهای LLM تقاضا زیاد، عرضه تقریباً صفر چطور بفهمی تغییری که در پرامپت یا مدل دادی، خروجی رو بهتر کرد یا بدتر؟ ساختن دیتاست ارزیابی، سنجش کیفیت، و لاگ کردن رفتار مدل در پروداکشن. تقریباً هیچ جونیوری این رو بلد نیست.

۳ فاندامنتال‌هایی که ارزششون بیشتر شد

وقتی تولید کد ارزون می‌شه، فهمیدن کد گرون می‌شه.

دیباگ کردن کدی که خودت ننوشتی خوندن لاگ، استک‌تریس، پروفایلینگ، و بازتولید باگ به‌صورت قابل‌تکرار. حالا که نصف کد رو AI می‌نویسه، همه‌ی کدها «کدی‌ان که خودت ننوشتی».
دیتابیس ایندکس، جوین، تراکنش، و اینکه چرا یک کوئری کنده. اکثر مشکلات پرفورمنس واقعی اینجاست و AI بدون دیدن دیتای واقعی نمی‌تونه حلش کنه.
طراحی API و درک HTTP استتوس‌کد، کش، احراز هویت، ورژنینگ، pagination، idempotency.
تست‌نویسی واقعی AI تست می‌نویسه، ولی تصمیم اینکه چی باید تست بشه با توئه. تست واحد، اینتگریشن، و مهم‌تر از همه داده‌ی مرزی.
خوندن کدبیس بزرگ و کد legacy فرصت پنهان دقیقاً همون‌جاییه که AI بدترین عملکرد رو داره (کانتکست محدود، وابستگی‌های نامرئی، دانش نانوشته). جونیوری که بتونه وارد یک پروژه‌ی قدیمی بشه و نقشه‌ش رو دربیاره، خیلی زود ارزشمند می‌شه.

۴ امنیت کدِ AI

مدل‌ها از نظر «کار کردن» تقریباً بی‌نقص شدن، ولی از نظر «امن بودن» جا موندن. این دو تا مسئله‌ی کاملاً جدا هستن.

رمزنگاری۸۷٪ قبولی
SQL Injection۸۳٪ قبولی
XSS۱۵٪ قبولی
Log Injection۱۲٪ قبولی

یعنی وقتی کد AI رو بازبینی می‌کنی، اول دنبال XSS و هندل کردن ورودی/خروجی بگرد، نه SQL Injection. میانگین کلی امنیت مدل‌ها حدود ۵۶٪ است و نسبت به سال قبل تقریباً تغییری نکرده.

حداقل چیزی که یک جونیور باید بلد باشه
  • OWASP Top 10 در حدی که ندونسته سوراخ باز نکنی.
  • XSS و escaping خروجی — ضعیف‌ترین نقطه‌ی کد AI.
  • IDOR — چک نکردن اینکه این کاربر اجازه‌ی دیدن این رکورد رو داره یا نه. AI تقریباً همیشه فراموشش می‌کنه.
  • مدیریت سکرت — کلید API توی کد یا ریپو، کلاسیک‌ترین اشتباه.
  • ولیدیشن ورودی سمت سرور — نه فقط سمت کلاینت.
  • اجرای یک اسکنر (مثل SAST یا `npm audit` / `pip-audit`) در CI.

۵ مهارت‌های عملیاتی

بیشترین ضعف جونیورها دقیقاً اینجاست — و سریع‌ترین جاییه که می‌شه جبرانش کرد.

Git تیمی برنچ، PR کوچک و تمیز، کامیت معنادار، rebase، حل کانفلیکت بدون ترس. حالا که حجم کد تولیدی بالا رفته، PR بزرگ یعنی کسی بازبینیش نمی‌کنه.
Docker و CI/CD در حدی که از پایپ‌لاین نترسی، سرویس خودت رو بالا بیاری و تست‌ها رو خودکار اجرا کنی.
کلاود پایه و مانیتورینگ دیپلوی، متغیر محیطی، لاگ ساخت‌یافته، متریک و یک alert ساده. بدونی وقتی سرویس می‌خوابه از کجا بفهمی.
مستندسازی و ثبت تصمیم README و ADR (ثبت دلیل تصمیم‌های معماری) که بقیه بتونن دنبالش کنن. این همون چیزیه که کانتکست ایجنت‌ها رو هم می‌سازه.

بخش دوم — چیزی که واقعاً استخدامت می‌کنه

۶ مهارت‌های انسانی

در مصاحبه‌ی ۲۰۲۶ سؤال «این کد چی کار می‌کنه» نیست؛ سؤال «چرا این‌جوری؟» است.

توضیح دادن دلیل تصمیم‌ها «گزینه‌ی دیگه چی بود؟ چرا اینو انتخاب کردی؟ اگه ترافیک ده‌برابر بشه چی می‌شه؟ چه چیزی رو فدا کردی؟»
مالکیت end-to-end از فهم نیاز کاربر تا دیپلوی و مانیتور. انتظار اینه که یک فیچر کامل تحویل بدی، نه یک فانکشن.
ارتباط مؤثر نوشتن خلاصه‌ی تصمیم، سؤال پرسیدن درست و به‌موقع، و بازخورد گرفتن روی PR بدون حالت تدافعی.
زبان انگلیسی بیشترین ضریب اثر برای مخاطب فارسی‌زبان خوندن مستندات و ایشوها، نوشتن PR و کامنت قابل‌فهم، و توان شرکت در یک مصاحبه‌ی انگلیسی. بدون این، بازار کارت به یک شهر محدود می‌مونه؛ با این، به کل دنیا وصل می‌شی.
دانش دامنه جونیوری که بیزنس رو می‌فهمه (فین‌تک، سلامت، لجستیک، آموزش) خیلی راحت‌تر استخدام می‌شه — چون AI کد می‌نویسه ولی نمی‌دونه کاربر واقعاً چی می‌خواد.

۷ مصاحبه در عصر AI

فرایند استخدام در ۲۰۲۶ عوض شده. اگه با ذهنیت قدیمی بری، حتی با مهارت خوب هم رد می‌شی.

✕ چیزی که داره حذف می‌شه

  • تسک خانگی (take-home) — چون معلوم نیست کار خودته یا AI. شرکت‌ها دارن کنارش می‌ذارن.
  • تست‌های خودکار الگوریتمی بدون حضور انسان.
  • حفظ کردن سؤالات LeetCode — مدل جواب می‌ده، پس دیگه سیگنال نیست.

✓ چیزی که جاش اومده

  • Live coding با حضور مصاحبه‌کننده — اغلب با اجازه‌ی استفاده از AI.
  • حل مشترک مسئله — مصاحبه‌کننده راهنمایی می‌ده و واکنش تو رو می‌سنجه.
  • فریم کردن مسئله: سؤال پرسیدن قبل از کد زدن.
  • اعتبارسنجی خروجی AI جلوی چشم مصاحبه‌کننده.
  • بلند فکر کردن و توضیح استدلال مهندسی.
چطور خودت رو برای این نوع مصاحبه آماده کنی
  • تمرین بلند فکر کردن: موقع حل تمرین، صدای خودت رو ضبط کن و توضیح بده چرا هر قدم رو برمی‌داری. سکوت = رد شدن.
  • قبل از کد زدن سؤال بپرس: حجم داده چقدره؟ کاربر همزمان چندتاست؟ چه چیزی خارج از محدوده‌ست؟
  • اگه AI مجاز بود، ازش استفاده کن — ولی بازبینی‌ش رو بلند بگو: «این پیشنهاد رو داد، ولی اینجا ورودی رو ولیدیت نکرده، اصلاحش می‌کنم.» این دقیقاً همون سیگنالیه که دنبالشن.
  • از قبل بپرس قانون استفاده از AI چیه. بعضی شرکت‌ها مجاز می‌دونن، بعضی ممنوع — پرسیدنش نشانه‌ی حرفه‌ای بودنه.
  • یکی از پروژه‌هات رو کامل مسلط باش: باید بتونی هر تصمیمش رو ده دقیقه دفاع کنی.

۸ پورتفولیو در ۲۰۲۶

وقتی تولید کد ارزون شده، وجود کد دیگه سیگنال نیست. سیگنال، قضاوت پشت کده.

✓ چیزی که کار می‌کنه

  • یک پروژه‌ی دیپلوی‌شده و در حال کار با لینک زنده
  • تست + CI سبز روی ریپو
  • README که مسئله، تصمیم‌ها و trade-offها رو توضیح بده
  • بخشی که نشون بدی: «این رو AI نوشت، من این‌ها رو اصلاح کردم، دلیلش این بود»
  • مشارکت واقعی در یک پروژه‌ی متن‌باز، حتی کوچک
  • یک کاربر واقعی — حتی یک نفر — که ازش استفاده می‌کنه

✕ چیزی که دیگه تمایز نمی‌سازه

  • حفظ کردن سینتکس
  • پروژه‌های آموزشی کپی‌شده از یوتیوب
  • لیست بلند فریمورک توی رزومه
  • «بلدم با ChatGPT کار کنم» به‌عنوان مهارت
  • ده تا ریپوی ToDo نیمه‌کاره
  • پروژه‌ای که فقط لوکال اجرا می‌شه

۹ چطور تجربه بسازی وقتی کسی جونیور استخدام نمی‌کنه

کلاسیک‌ترین بن‌بست: تجربه می‌خوان، ولی بدون کار تجربه‌ای شکل نمی‌گیره. این چهار راه واقعاً جواب می‌ده.

متن‌باز، ولی درست از رفع تایپو شروع نکن. یک پروژه‌ای که خودت ازش استفاده می‌کنی انتخاب کن، ایشوهاش رو بخون، یک باگ کوچک واقعی رو درست کن. یک PR مرج‌شده‌ی معنادار از ده PR الکی ارزشمندتره.
حل یک مشکل واقعی برای یک آدم واقعی یک ابزار کوچک برای کسب‌وکار یکی از آشنایان، یا اتوماسیون یک کار دستی تکراری. اینکه بتونی بگی «این الان هر روز استفاده می‌شه»، از هر پروژه‌ی نمایشی قوی‌تره.
فریلنسِ کوچک و هدفمند چند پروژه‌ی کوچک ولی کامل (با تحویل، بازخورد و اصلاح) تجربه‌ی واقعی کار با مشتری می‌سازه — چیزی که در مصاحبه حرف برای گفتن می‌ده.
علنی یاد بگیر چیزی که یاد می‌گیری رو بنویس یا منتشر کن. خیلی از استخدام‌های جونیور از طریق دیده شدن و معرفی اتفاق می‌افته، نه فرم ارسال رزومه.

بخش سوم — از کجا شروع کنم

مسیر ۹۰ روزه

اگه از صفر می‌خوای شروع کنی، این ترتیب کمترین اتلاف وقت رو داره. هر فاز روی خروجی قبلی سوار می‌شه — آخرش یک پروژه‌ی زنده داری، نه چهار تا نیمه‌کاره.

هفته ۱–۳

فاندامنتال + Gitیک زبان رو محکم کن (Python یا JS)، دیتابیس رابطه‌ای، و Git تیمی. هر روز یک PR کوچک روی ریپوی خودت.

هفته ۴–۶

یک پروژه‌ی واقعی بسازیک API با احراز هویت، دیتابیس و تست. با AI بنویس، ولی هر خط رو بازبینی کن و دلیل تصمیم‌ها رو در README ثبت کن.

هفته ۷–۹

دیپلوی و عملیاتداکرایز کن، CI بساز، روی یک سرویس ابری بالا بیار، لاگ و مانیتورینگ اضافه کن، و یک بار امنیتش رو بازبینی کن. حالا یک لینک زنده داری.

هفته ۱۰–۱۲

لایه‌ی AI + دیده شدنیک قابلیت مبتنی بر LLM اضافه کن (جست‌وجوی معنایی، خلاصه‌سازی، دستیار) به‌همراه یک eval ساده. بعد رزومه، گیت‌هاب و لینکدین رو حول همین یک پروژه بازنویسی کن و شروع کن به توضیح دادنش.

اگه وقت کمتری داری — نسخه‌ی فشرده‌ی ۳۰ روزه
  • هفته ۱: یک پروژه‌ی کوچک ولی کامل انتخاب کن (یک API با سه endpoint معنادار).
  • هفته ۲: تست بنویس، امنیتش رو بازبینی کن، README با ثبت تصمیم‌ها بنویس.
  • هفته ۳: داکرایز + CI + دیپلوی. لینک زنده بگیر.
  • هفته ۴: یک قابلیت AI اضافه کن و یک پست بنویس درباره‌ی اینکه چی ساختی و چرا این‌جوری.

این صفحه رایگان و متن‌بازه — Fork کن، تغییر بده، و برای تیمت استفاده کن. اگه نکته‌ای جا افتاده، Pull Request بفرست.
